# Paper Compass 文档中心

项目文档按读者分为两类：使用网站和 MCP 的用户，维护、开发或自托管项目的开发者。部署与运维也归入开发者文档。

| 文档入口 | 适合谁 | 主要内容 |
| --- | --- | --- |
| [用户文档](user/README.md) | 网站用户、使用 MCP 的研究者 | GitHub 登录、收藏与已读、连接 Agent、论文检索示例 |
| [开发者文档](developer/README.md) | 开发者、维护者、自托管管理员 | 本地开发、配置、接口、采集与分类、数据库、部署运维、测试和研究报告 |

```text
docs/
  README.md          文档总入口
  user/              用户手册
  developer/         开发者手册
    admin/           采集、分类、部署与维护
    reports/         测量报告及证据附件
    generated/       Python API 参考页
  img/               共享图片，保留现有网站资源地址
  index.rst          Sphinx 开发者参考入口
  conf.py            Sphinx 构建配置
```

## 网站展示规则

网站文档导航只展示 `DocumentationRepository.CATALOG` 显式登记的用户手册。目前为 MCP 用户指南、账号与文献库两篇；目录索引不额外占用网站导航。

开发者文档、内部报告和部署说明不会因为放入 `docs/` 而出现在网站中。它们仍可从源码仓库阅读，网站白名单不等于仓库访问控制。

## 文档维护规则

1. 新文档先确定读者，放入 `user/` 或 `developer/`，并更新对应索引。
2. 用户文档聚焦操作说明、连接方式和使用示例，不包含服务器路径、凭据或运维步骤，也不链接开发者材料。
3. 需要在网站展示的用户手册须单独加入公开白名单；不要通过扫描整个目录自动公开文件。
4. 图片继续放在 `img/`。用户 Markdown 使用 `../img/...`，网站会转换为原有 `/api/docs/assets/img/...` 地址。
5. 移动或重命名文件时，同步更新相对链接、项目 README、交接文档、Sphinx 目录和相关测试。报告附件整体保留，不改写历史测量结果。

旧的自定义文档目录仍支持平铺的 `MCP_USER_GUIDE.md` 和 `ACCOUNT_USER_GUIDE.md`，便于已有部署升级。新目录中的同名用户手册优先读取。
