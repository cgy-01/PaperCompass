# DeepSeek 论文分类 Token、耗时与费用实测归档

- 实测日期：2026-11-18；归档日期：2026-11-19。
- 时间区间：2026-11-18T23:55:23.874718+08:00 至 2026-11-18T23:55:35.194417+08:00，均为北京时间（UTC+8）。
- 性质：10 篇真实论文、真实 API、串行抽样。未执行一万篇重分类；本报告不是全库实测或提供商扣款凭证。
- 面向维护者，仅归档于源码文档，不加入网站公开用户文档白名单。

## 1. 可用于规划的结论

在本次提示词、完整标题与摘要、Flash 非思考模式和观测到的缓存条件下，每篇平均处理 1.1326 秒；按 12,270 篇可用文本线性外推，连续处理约 3.8603 小时，空闲价约 11.2141 元。对执行计划建议预留 **4–6 小时、15–20 元**；若官方缓存完全失效，空闲价基线约 27.8369 元，可按约 35 元准备。高峰价格情景单独列出，不把全程空闲价当作任何时间执行的保证。

默认每轮 200 篇、分类定时器每天一次，则约需 62 个批次日。4–6 小时是放宽批次及日额度后的连续工作量，不是当前默认调度下的日历完成时间。这里没有修改任何额度或启动全库任务。

原始路径为 `.runtime-demo/matched_entries_history.before-complete-conferences.db`；补全副本为 `tmp/semantic-small-all-20261118-7mam1hcs/matched_entries_history.db`。数据库全部以 SQLite `mode=ro` 读取，没有更新原始库。数据文件的大小、修改时间与 SHA-256 见 [dataset_fingerprints.json](dataset_fingerprints.json)。

按 `标题字符数 + 完整摘要字符数` 排序，在十个等分区间的中间位置各取一篇，位置为 `floor(N × (i + 0.5) / 10)`，i=0…9；同长度按标题排序。不根据已有分类标签挑选样本，旧语义分类结果不作为本次模型输入。全体可用文本平均长度约 1,393.49 字符，样本平均长度 1,392.3 字符。

这是按文本长度分层的便利样本，不是研究主题、会议、年份全面均衡的样本，也不是随机准确率测试。10 次成功仅表示输出通过结构和证据校验，不能解释为分类准确率 100%。

正常数据库队列还会跳过 46 篇 `demo_topic` 示例记录，因此实际可分类有效量约 12,224；报告为延续上次说明，主口径仍取 12,270，并同时给出其他分母。55 篇缺信息论文在补齐前不会调用模型；12,325 情景是假定全体信息最终可用。

输出上限 512 不是每篇实际收费输出量，本轮实际每篇输出 69–106 Token。服务端没有返回可独立记录的 reasoning_tokens 字段，不能把“字段未返回”写成实测零；本轮记录的是显式请求了非思考模式。

## 6. 用时口径

- **API 阶段墙钟**：本地请求账本 `started_at` 到 `finished_at`，包含预算登记附近的开销、请求传输、提供商等待/推理、响应读取与校验；不是服务端 GPU 推理时间。合计 11.273039 秒，平均 1.1273039 秒。
- **单篇处理墙钟**：抽样脚本在本地缓存查询前启动计时，至返回并保存缓存后结束。包含 API 阶段及本地 SQLite/解析开销；逐篇只保留到毫秒。合计 11.326 秒，平均 1.1326 秒。
- 单篇处理中位数 1.132 秒，最小 0.939 秒，最大 1.417 秒。样本不足以给出可靠 P95/P99 或全库 SLA。
- **批次总耗时**：原脚本记录 11.34 秒，包括批次初始化和汇总等额外开销。不同口径和记录精度会出现小差异，不应强制完全相等。

原始 API 阶段时间来自 [request_ledger.json](request_ledger.json)；单篇秒数来自原抽样结果，不是之后再次调用测得。此次归档没有新发起收费请求。

## 7. 单价、公式和账本差异

归档时于 2026-11-19 复核 [DeepSeek 官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，Flash 对应单价如下，单位均为人民币/百万 Token：

| 情景 | 未缓存输入 | 缓存输入 | 输出 |
| --- | ---: | ---: | ---: |
| 空闲时段 | 1 | 0.02 | 4 |
| 高峰时段 | 2 | 0.04 | 8 |

官方列出的北京时间工作日高峰为 09:00–12:00、14:00–18:00（不含中国法定节假日）；其他时段为空闲。本次调用位于 23:55，因此使用空闲价折算。价格可变，长期预算需重新核对。

```text
单次费用 = (未命中输入Token × 输入单价
          + 命中输入Token × 缓存单价
          + 输出Token × 输出单价) / 1,000,000

10篇空闲价 = (5,407 × 1 + 13,824 × 0.02 + 864 × 4) / 1,000,000
           = 0.00913948 元

10篇高峰价 = 0.01827896 元
```

项目为守住预算，始终按配置的高峰单价估算记账，并逐次向上取整到微元。因此内部账本为 **0.018284 元**，比不逐次取整的高峰计算多 **0.00000504 元**。这不是本次平台实际扣款金额，也不是额外调用。

请求前预留额合计为 0.236770 元，预留 Token 合计 103,025；收到有效 usage 后均已按实际用量结算。预留是控制额度的上界估计，不等于实际输入或实际费用。未知用量请求为 0。

**本轮没有查阅提供商支付流水，不能宣称“平台已实际扣款 0.00913948 元”。** 该值为根据真实 usage 与所列官方单价计算的费用预期。

## 9. 当前限额与日历时间

测量时的默认控制为：每轮 200 篇、每天分类定时器一次、请求上限 500/日、Token 用量/预留上限 1,000,000/日、估算预算 1 元/日。自然日按北京时间切换。

- 12,270 / 200 向上取整为 **62 个批次日**。其前提是每天都能处理满 200 篇、没有新任务竞争额度、没有失败/复核、没有缺摘要项占批次；不是实际完成日期承诺。
- 若只提高单轮上限，请求数 500/日仍给出至少 **25 个请求日**；Token 与预留规则可能进一步收紧，不能据此保证 25 天完成。
- 每篇约 2,009.5 Token，200 篇约 401,900 Token；在本次缓存比例下，项目高峰单价估算约 0.3656 元/200篇，未含预留余量和逐次取整差异。缓存全失效时约 0.9075 元/200篇，更接近日预算，可能提前停下。
- 要连续 4–6 小时完成大部分有效记录，需要预先评估并临时调整批次、日请求、日 Token 和日费用额度，同时安排执行时段。**本报告没有修改任何限额，没有启动全库重分类。**

## 10. 2核 / 2GiB 的适配证据

目标云服务器为 2 核 CPU、2 GiB 内存；真实 API 速度在本地 WSL 测量，未在云服务器测量。该工作主要等待远程模型，采用串行请求，无本地向量模型加载。

另一次独立的模拟资源检查使用 10,201 条合成记录，处理并发布 200 条增量，峰值 RSS 为 79.94 MiB。详见 [simulated_resource_smoke.json](simulated_resource_smoke.json)。该测试使用模拟 API，不能用于推断真实调用吞吐、远端延迟或云服务器峰值内存。分类服务模板设置半核 CPU 配额、256 MiB MemoryHigh、384 MiB MemoryMax，以保护网站；部署后仍需观察实际 RSS、磁盘和队列。
