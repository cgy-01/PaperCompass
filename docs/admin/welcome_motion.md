# 宣传首页动效测量与实现

本次参数来自用户提供的 `website.mp4`：1920 × 1080，30 fps，共 120 帧，时长约 4 秒。原片、抽帧、时间接触表和测量 CSV 位于本地 `tmp/motion-reference/`，已由现有 `.gitignore` 排除，不进入源码发布。

## 计时基准

录制的前 8 帧是刷新前已经展示完毕的页面。从第 8 帧（约 0.267 秒，帧号从 0 开始）起，新的页面只剩顶栏与背景。不能把录制开始直接当成新页面的绘制开始。

下表“首次可见”按图像变化估计，不等同于源 CSS 的精确 delay。30 fps 的单帧间隔为 33.3ms；视频压缩、文字亚像素渲染与浏览器缩放都会引入测量误差。

| 元素                     | 录制中的首次可见 | 扣除刷新前画面后 | 视觉上基本稳定      | 动效形式                                                  |
| ------------------------ | ---------------- | ---------------- | ------------------- | --------------------------------------------------------- |
| 顶栏、背景               | 新页面首帧即显示 | 0 秒             | 静态                | 没有观察到入场动画                                        |
| 三行主标题整体           | 约 0.83 秒       | 约 0.57 秒       | 约 1.57–1.80 秒     | 淡入、上移约 24 个录制像素，模糊约 4px 渐清晰；无可见弹跳 |
| 说明文字                 | 约 1.33 秒       | 约 1.07 秒       | 约 1.93–2.20 秒     | 淡入、上移约 16 个录制像素                                |
| 眉题、按钮、读者信息     | 约 1.77–1.80 秒  | 约 1.50–1.53 秒  | 约 2.30–2.57 秒     | 基本同时入场，小幅上移，轻微缩放和模糊收敛                |
| 右侧终端、曲线、摘要区域 | 约 1.80 秒       | 约 1.53 秒       | 外框约 2.20–2.40 秒 | 整组淡入和轻微上移；终端内部随后仍在变化                  |
| 底部滚动提示             | 约 1.80 秒       | 约 1.53 秒       | 约 2.30–2.80 秒     | 淡入、轻微上移                                            |

标题三行没有观察到逐行交错，作为一个整体进入。整体节奏是重叠式，而不是等待前一组完全结束再播放下一组。录制只包含首屏，不能据此推断下方页面的滚动动效。

## 测量方法与限制

1. 使用 `ffprobe` 确认帧率与时长，`ffmpeg` 解码全部 120 帧。
2. 用刷新后的空白背景作为基准，对标题、小字、按钮等分别划定区域。
3. 将后期稳定画面作为模板，拟合每帧的透明度、水平和垂直位移、Gaussian 模糊；右侧持续变化的终端文字不用于判断整个区域何时完成。
4. 对标题的位移及透明度曲线拟合，得到近似 `cubic-bezier(0.20, 0.38, 0.19, 0.95)`。这是视觉拟合结果，不是对参考站源代码参数的断言。

主标题早期几个样本（时间为录制时间）：

| 时间     | 估计透明度 | 剩余向上位移 | 估计模糊 |
| -------- | ---------- | ------------ | -------- |
| 0.833 秒 | 0.06       | 20.8px       | 3.9px    |
| 0.900 秒 | 0.19       | 18.0px       | 3.2px    |
| 1.033 秒 | 0.58       | 9.7px        | 1.6px    |
| 1.233 秒 | 0.82       | 4.5px        | 0.9px    |
| 1.433 秒 | 0.96       | 1.6px        | 约 0.2px |

录制像素不一定等于原站 CSS 像素。小元素的微小缩放、模糊难以与视频压缩完全分离，因此下列 CSS 位移和缩放是便于维护的近似复现值。

## Paper Compass 参数

以页面首次绘制为起点，参数统一放在 `system/frontend/styles/welcome.css`：

| 分组         | 开始    | 持续    | 结束    | 初始位移 / 缩放 / 模糊 |
| ------------ | ------- | ------- | ------- | ---------------------- |
| 主标题       | 0.55 秒 | 1.00 秒 | 1.55 秒 | 24px / 1 / 4px         |
| 说明文字     | 1.05 秒 | 0.85 秒 | 1.90 秒 | 16px / 1 / 1px         |
| 其余首屏内容 | 1.50 秒 | 0.70 秒 | 2.20 秒 | 12px / 0.98 / 2px      |

顶栏与背景保持静态。下方论文预览仍来自真实文献库。按后续设计要求，首屏右侧采用三层展示：

- 第一层为用户指定的 `train.py` 训练日志演示，20 行为一段，复制两段进行无缝循环；30fps 画面对比显示约每 0.5 秒上移 17 像素。当前开发者终端使用 12px、500 字重、1.7 行高，每段高 408px、12 秒一轮，保持约 34px/s 的速度。命令暖橙色 `#D98550`，Git 提交及检查点成功信息青绿色 `#69B69C`，其余日志暖灰色 `#A6998E`。字体优先 JetBrains Mono，回退 Fira Code、SF Mono、monospace，仅使用本机可用字体。容器圆角 8px，无实体边框，使用轻微内描边和柔和阴影；日志可视窗口铺满容器，上下不留内边距，左右保持 20px，长行不折行，可横向滚动。红黄绿圆点与 `train.py` 固定在左上角的底层，代码轨道在其上方滚动；标题灰度与 Loss Curve 相同，不显示“训练演示”文字。日志从底边进入、顶边裁切，离开页面或切入后台时暂停，鼠标悬停或聚焦也暂停。
- 第二层为 Canvas 绘制的演示 Loss Curve，最终值 0.891 对应同组日志，作为视觉演示，不表示平台在实时训练模型。
- 第三层为真实“近 30 天新增”数量，直接复用工作区 `/api/v1/bootstrap` 中的 `overview.recent30`，按公开日期统计；点击进入发现页并应用 `days=30`。不增加独立统计接口或数据库查询。

三个气泡最初参考高度分别约 186、120、82px，间距 15px，沿用平台配色。中文排版调整后，信息条可随文字自然增高。训练日志与曲线是演示，第三层及下方文献是实际数据，互不混用。

终端当前高度按 10 个代码行高计算：`12px × 1.7 × 10 = 204px`。CSS 变量统一控制字号、行高和容器高度，不再通过标题位置动态裁切高度；用顶部留白保留原有 252px 布局占位，因此下沿及下方两个气泡不移动。横向滚动保留，但隐藏滚动条，避免占用代码可视高度。

参考本地 `tmp/base.png`，三张卡片共用一个半透明预览舱底板：桌面圆角 30px、12px 背景模糊、细描边与柔和阴影，首尾卡片略微突出；Loss Curve 采用暖橙色细边。底板由 `.welcome-desk::before` 绘制，独立层叠且不拦截点击，不改变卡片尺寸、滚动周期或布局占位。手机端收窄底板外扩范围、圆角 24px，关闭背景模糊以减少绘制开销。

中文排版角色统一在最后加载的 `styles/typography.css` 中维护：系统中文字体回退、正文 16px/1.7、卡片正文 15px/1.65、辅助文字 13px/1.5、长文最大 36em。标题保留原字号与响应式断点，字重不超过 600，不加载中文 webfont。英文训练日志的独立字体角色与滚动周期在 `welcome.css` 维护。

`typography.js` 只规范 DOM 文本的中英文间距和全角标点间距；原始元数据、筛选值、URL、输入框和代码内容不改写。动态渲染也通过同一显示层处理。

手机端保留时序，但将入场模糊关闭，降低栅格化开销。系统开启“减少动态效果”时直接显示所有内容。切换到后台标签页时暂停，进入工作区时不播放首屏动效。CSS 独立于数据请求执行；JavaScript 或后端暂时不可用时，静态内容仍能正常出现。
