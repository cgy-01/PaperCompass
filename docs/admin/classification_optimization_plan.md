# RFC：论文语义多标签分类与数据飞轮

状态：实施计划，尚未实施向量分类或模型训练。用于建立一份可跟踪的 GitHub Issue。

## 1. 问题与现状

Paper Compass 对论文标题、摘要和出版来源进行整理，支持按研究主题浏览。当前分类问题包括跨领域漏收、泛词误收、主题主次判断粗糙，以及缺少独立标注数据来衡量改进。

典型案例是 *Marathoner: Ultra-Long-Horizon Autonomous Intelligence*：虽然挂在 arXiv cs.CV，但研究对象是长时自主 Agent，涉及后训练与强化学习。arXiv 分类不能决定它可以进入哪些研究主题。该论文只作为离线案例，本计划不要求回补其历史记录。

需要区分两个代码状态：

- 本地 `main` 的已提交基线为 `54ebdf1`，分类主要使用正则匹配；既有向量排名模块 `processors/st_ranker.py` 不承担主题分类。
- 当前本地工作区另有尚未提交、尚未部署的 `evidence-v1` 规则实验：统一分类入口、贡献句加权、歧义约束、候选保留与主主题排序。它仍是规则系统，不能当成已上线的语义分类器。

正式实验分别保留“已提交规则基线”和“本地证据规则实验”的版本与结果，不把未部署代码描述为线上能力。

本任务是**少量标注条件下的学术论文多标签分类**，包含独立的候选召回、标签判定、主主题选择和持续学习步骤。

## 2. 目标、范围与约束

### 2.1 目标行为

1. 依据标题和完整摘要的语义分类，不要求出现特定关键词。
2. 一篇论文可同时属于多个主题，研究对象、主要贡献和所用方法可以分别记录。
3. 分类不确定时允许待确认，不强行分给最相近的一个主题。
4. 形成真实样例、模型建议、人工纠错、独立评估、版本发布的数据飞轮。
5. 新论文按后台增量流程获得分类结果，前端和 MCP 继续读取已发布查询库。

### 2.2 保持不变

- 不修改权威原始数据库表结构，不替换原始库，不改变论文 ID、收藏或账号数据。
- 保持现有 Web API、MCP 参数与返回字段兼容；内部分类概率不写入现有 `rank_score`，不改变检索排序分数的含义。
- 不改前端布局、动效或导航，不新增面向访客的模型配置流程。
- 不升级现有生产依赖。新增研究库需要独立实验环境；候选方法先验证导出或隔离运行能力，不能直接改生产依赖锁定版本。
- 不调整现有抓取来源、定时器时间和 arXiv 成功水位，不下载或长期保存全库 PDF。
- 不触发历史补抓，不自动把既有全库纳入向量计算或重分类。旧论文只允许离线抽样评估；历史上线重处理需要另立范围与任务。
- 分类模型不随 Web/MCP 服务启动，不把向量运算或 LLM 请求放到用户请求路径。

### 2.3 第一版不做

不自动扩展顶层主题、不训练基础大模型、不建立全量引用图、不新增复杂向量数据库、不把用户点击或收藏直接当成正确主题标签。

## 3. 分类定义先于模型选择

沿用现有 14 个稳定主题 key：

| key | 主题 |
| --- | --- |
| `llm` | 大模型 |
| `agents` | AI Agent |
| `ai_infra` | AI Infra |
| `reasoning_post_training` | 推理与后训练 |
| `multimodal_generative` | 多模态与生成模型 |
| `ai_safety_alignment` | AI 安全与对齐 |
| `data_evaluation` | 数据与评测 |
| `embodied_robotics` | 具身智能与机器人 |
| `reinforcement_learning` | 强化学习与决策 |
| `ai_for_science` | AI for Science |
| `vision_graphics` | 视觉与图形 |
| `ml_foundations` | 机器学习基础 |
| `language_speech_retrieval` | 语言、语音与检索 |
| `systems_architecture` | 系统与计算架构 |

每个主题维护包含范围、排除条件、正例、难负例、允许交叉的方向以及主主题判定说明。主题名称本身不能替代完整定义。

需要优先明确的边界：

- LLM：明确的大语言模型研究；区分“研究对象/贡献”和“仅作为工具或基线”。不能凭任意神经网络或参数数字归入。
- 数据与评测：明确发布、构建、治理数据，提出针对数据或评测本身的方法；仅在已有数据集上报告实验不算。
- AI Infra：对训练、推理、Serving、通信、调度、存储或硬件系统有实质研究贡献；仅提到速度、GPU 或 latency 不算。
- Agent 与后训练/RL：允许交叉，主主题根据主要研究问题与贡献判定，不能按菜单顺序或词组长度确定。
- AI 对齐与图像/几何对齐：标签定义与负例需要明确区分。

标注时额外记录角色：`research_target`、`contribution`、`method_used`、`background`。这些是内部研究特征，不是新增前端主题。具体哪些角色足以获得某主题，由该主题规范明确；不能用同一条宽泛规则处理所有主题。

## 4. 数据集与标注协议

### 4.1 数据来源

使用已配置来源取得的真实标题与摘要，覆盖 arXiv、会议、不同研究方向、不同摘要长度与时间批次。离线抽样可只读已有记录，不改它们的线上标签。

采样不能局限于旧规则命中或当前已有主题的论文。需在已配置来源范围内保留规则排除项的抽样，否则无法测量源头漏收。

实施阶段先建立有保留期和空间上限的候选元数据队列，供语义判定与拒绝项抽查使用。候选队列不等于公开论文库，只有标题、摘要、稳定身份和来源等必要元数据，不收集 PDF。

### 4.2 标注内容与质量层级

每条样例记录：稳定论文身份、原始文本哈希、标题、摘要、来源、主主题、多标签、各标签角色、原文证据片段、排除理由、标注者/模型版本、规范版本、审核状态及时间。

- **模型建议集（silver）**：LLM 建议或伪标签，可用于辅助训练，不能自动变成标准答案。
- **人工确认集（gold）**：按规范确认的真实论文。冲突案例需要复核、裁决并记录原因。
- **合成样本集**：LLM 构造的文本单独标记，只用于受控增强实验，不计入真实样例数或测试集。

不接受仅有标签、没有可核验依据的高质量标注。模型证据片段应能在对应版本的标题/摘要中定位；缺摘要或信息不足时允许无法判断。

### 4.3 初始规模与划分

以下是启动预算建议，需通过首轮标注验证工作量，不是样本数量达到后即可保证准确率：

1. 先做约 100 篇试标，修订边界与标注说明。
2. 建立训练/样例池约 200–300 篇、验证集约 100–150 篇、自然流量分布的冻结测试集约 200–300 篇。
3. 另建约 100–200 篇挑战集，覆盖 Agent、AI Infra、LLM/工具使用、数据/普通实验、跨来源论文和困难负例。挑战集不与自然分布测试集混成一个总体准确率。
4. 每个主题尽量包含足够正例与难负例；单主题测试正例少于 30 时标记证据不足，补充样本或报告较宽置信区间，不宣称该主题已可靠验收。

按论文家族划分：arXiv 版本、会议版本和高置信重复记录归到同一侧。使用 arXiv ID、DOI及经核对的标题关系分组，避免把不同论文错误合并。新时间批次另做时间外推测试。

验证集用于模型选择、阈值和校准；测试集不进入样例检索、提示词或训练。已用于反复调参的测试集应转为开发集，再冻结一批新测试数据。

## 5. 实验矩阵：分别检验表示与分类方法

### 5.1 基线与候选

| 编号 | 方法 | 验证问题 |
| --- | --- | --- |
| B0 | 已提交版本的规则分类 | 实际旧基线是什么 |
| B1 | 本地 `evidence-v1` 实验 | 规则增强本身带来多少收益与损失 |
| B2 | TF-IDF + One-vs-Rest 线性分类 | 监督学习是否已能解决大量边界问题 |
| B3 | 冻结文本向量 + 多原型/近邻样例 | 少标注、无需训练的语义分类能达到什么水平 |
| B4 | 冻结文本向量 + 多标签分类头 | 学习类别边界是否优于纯相似度 |
| B5 | SetFit 等少样本适配 | 微调编码器是否值得额外训练成本 |
| B6 | GLiClass 等标签描述驱动模型 | 标签定义能否减少对样例数量的依赖 |
| B7 | LLM + 真实样例 + 证据输出 | 作为质量与成本对照，不直接当作真值 |

先完成 B0–B4，达到瓶颈后再按预算测试 B5–B7。不要同时重训所有研究框架。

### 5.2 向量表示

至少比较现有 MiniLM 基线、一种科学论文编码器（如 SPECTER2 的分类适配表示），以及一种可覆盖完整摘要的通用编码器。SciMult 等作为后续候选，选择依据是本项目测试结果，不能假设科学领域编码器一定优于通用模型。

第一步使用标准化的“标题 + 完整摘要”。输入长度、分词数及截断情况必须记录：MiniLM 默认 256 word pieces 的限制不能被忽略。超长摘要采用明确的分段/聚合策略或足够上下文的模型，不能静默丢弃后半段。

先得到联合文本向量，再做消融实验比较：标题独立向量、摘要句子级多向量、LLM 提取的研究对象与贡献、标签定义向量及相似样例特征。只有经过验证有收益的要素进入正式管线。

记录模型与 checkpoint revision、输入模板、分段/池化/归一化策略、维度和文本哈希。不同模型或处理版本的向量不能直接混用。更换编码器需要建立独立向量版本；修改样例通常可以复用已有论文向量。

### 5.3 多标签与主主题

- 每个主题独立判定，使用逐标签阈值，不能用总和为 1 的单标签 softmax 强制选一类。
- 近邻方法用经过确认的正例和难负例共同判断。多标签任务中，其他主题的正例不能自动当成本主题负例。
- 分类头从简单、可导出的小模型开始；类别权重、阈值、概率校准均在验证集决定。
- 主主题是独立输出，根据主要研究对象与贡献判定；多标签得分可以辅助，不能把最高余弦相似度直接当作充分依据。
- 原始相似度和 LLM 自报置信度不是准确概率。只有经校准且评估充分的分数才可用于自动通过策略；不向用户展示“相似度等于正确概率”的百分比。
- 各标签支持通过、未通过、证据不足。定义单标签拒判及整体待确认策略，保留合理候选的检索能力。

## 6. 数据飞轮与 LLM 的分工

```text
来源范围内的新论文元数据
  -> 完整文本表示 -> 语义分类与边界检测
  -> 低确定性 / 方法分歧 / 新颖或长尾样本 + 随机抽查
  -> LLM 提炼对象、贡献、标签建议及可核验证据
  -> 人工确认或裁决 -> 真实样例库与规范修订
  -> 更新原型 / 训练分类器 / 调整阈值
  -> 独立评估 -> 新分类版本
```

LLM 用于标签定义草拟、样例整理、疑难案例建议和主动选样。它不是所有样例的最终裁判。两个模型一致也不能证明标签正确，模型自身反复确认不能代替独立审核。

选样综合不确定性、类别间边界、规则/模型分歧、语义多样性、长尾覆盖与规则排除项的随机审计。对常见标签和近重复论文设置采样上限，避免样例池被 LLM 大类占满。

保留人工纠正前后值、证据、规范版本和数据谱系；有问题的模型批次可以撤销，不将其污染永久传递到 gold。点击和收藏只说明兴趣，主题正确性反馈必须单独确认。

API 调用需要显式配置，具备单日预算、请求上限、超时、有限重试、并发限制及断路/暂停机制。模型中断不阻塞原有采集与公开阅读。付费调用、模型训练和整批重处理不随部署默认启动。

## 7. 与当前架构的集成

### 7.1 独立派生存储

新增一个可迁移、可备份的 `classification.db`，不改变权威原始数据库的结构。建议包含候选元数据/任务、向量、样例及审核、标注事件、分类结果、运行版本与评估报告索引。具体表结构在实现阶段独立设计并测试；这些表目前尚不存在。

它保存可重建的向量和结果，也保存需要持久备份、不能随缓存清理的人工标注与裁决记录。两者应明确区分保留策略。

每个结果至少关联：论文身份、文本哈希、分类结果/状态、taxonomy/encoder/classifier/prompt/exemplar 版本、证据来源及时间。向量缓存只依赖文本与编码流程；分类结果缓存还依赖主题规范、分类器、阈值和样例版本。

### 7.2 后台增量流程

1. 采集器在已配置来源范围内保存受空间/保留期约束的候选元数据，不先依赖旧主题词把所有不命中项永久丢弃。
2. 在已有范围内完成去重、版本检查和原始记录提交，短事务结束后再调度后台分类，网络调用期间不持有原始库写锁。
3. 独立 worker 批量向量化、分类与提交派生结果；按任务键 `论文身份 + 文本哈希 + 管线版本` 保证幂等。失败保留可重试任务与错误，重复投递不创建重复论文。
4. 结果使用时核对文本哈希；旧摘要计算完成的结果不得覆盖新版本。区分元数据不全、模型不可用、待复核和已完成，不用空标签冒充成功。
5. 查询库构建读取一致的分类结果批次，沿用候选快照校验和原子发布机制。在线 API 不调用编码器或 LLM。

特别注意：现有 `query_store` 依赖原始记录指纹。异步分类完成时，原始标题/摘要可能没有变化。实现时必须增加**分类结果变更驱动的逐论文增量更新**，否则后台已有标签而网站永远不显示。不能通过伪造 `matched_date`、改写作者/摘要、全局改格式版本或清空历史指纹来触发更新。

默认只纳管新版本启用后新增或内容变化的论文，以及这些论文后续完成的分类/审核事件。不把全库 ID 加入队列。查询构建的全局签名不能因为换模型就隐式触发历史全量处理。

### 7.3 模式与故障处理

建议新增配置模式 `rules`、`shadow`、`semantic`，这些是拟议字段，目前不存在：

- `rules`：默认兼容模式，继续使用已批准的规则行为。
- `shadow`：计算语义结果和对照报告，不改变公开标签。
- `semantic`：仅把已纳管新记录的合格结果写入查询快照；不确定项按既定候选策略保留。

worker 与 Web/MCP 进程分离。嵌入可选在本地开发设备、隔离批处理进程或 API 后端完成；对现有小规格服务器先测内存/耗时，再选择执行位置，不能让 Web 进程常驻 PyTorch 模型。

模型或 API 故障时，按照显式策略使用规则兜底或保留待确认状态，记录实际来源与降级原因，不宣称语义分类成功。原始抓取成功水位和分类任务进度分别管理，不能用同一个游标互相覆盖。

## 8. 评估指标与候选发布门槛

### 8.1 质量指标

- Macro-F1、Micro-F1，每主题 Precision/Recall/F1、样本支持数及置信区间。
- Agent、AI Infra、LLM、数据与评测分别报告，不能只看总体分数。
- 主主题准确率单独报告，不能与多标签 F1 混用。
- 候选召回率、拒判率/自动覆盖率、拒判项抽查错误率，避免通过大量拒判提高表面准确率。
- 自然分布测试集、挑战集、时间外推集、缺摘要子集分开报告。
- 如果输出概率，报告校准表现；模型自报分数不能代替校准评估。

### 8.2 运行指标

每千篇分类耗时与 API 成本、批处理峰值 RSS、向量/标注存储增长、积压任务量、重试/失败率、源数据到查询发布延迟，以及分类任务运行时 Web API P95 延迟。

### 8.3 建议上线条件

以下为需要实验验证的候选门槛，不是已经达到的指标：

1. 冻结测试集 Macro-F1 相对已提交规则基线至少提高 0.03（3 个百分点），并报告与本地证据规则实验的对比。
2. Agent、AI Infra 的 Precision 与 Recall 均不低于基线；LLM 和数据与评测的严格边界挑战集不退步。
3. 在验证集选阈值时，以重点主题 Precision 0.90 为初始约束目标；达不到时继续研究或降低自动覆盖，不通过改测试集或把低分项全部隐藏来宣布成功。测试集是否达到目标必须如实报告。
4. 关键主题样本支持不足或置信区间无法支持结论时，继续 shadow 并补充数据；不能只凭点估计上线。
5. 控制既定负载下，Web API P95 延迟较同机基线增加不超过 10%；不增加 Web/MCP 常驻模型内存，后台进程不能触发服务已有内存硬限制。
6. M0 必须给出可测的日处理量、成本、积压清理时间与磁盘预算；超预算暂停自动发布，不绕过预算偷偷调用模型。
7. 通过身份/收藏兼容、原始库安全、幂等、版本竞态、失败回退与原子发布测试。

## 9. 分阶段执行与交付

- [ ] **M0：冻结范围与标注规范。** 确认本地/线上基线，完成 14 类定义、约 100 篇试标、资源/费用预算和数据集划分方案。先不自动修改主题集合。
- [ ] **M1：样例库与评估框架。** 建立 gold/silver/合成数据分层、重复论文分组、独立验证/测试集、评估脚本和 baseline 报告。完成本文涉及的外部模型许可证与兼容性核对。
- [ ] **M2：表示与分类实验。** 完成 B0–B4、完整输入/长摘要检查、科学与通用编码器比较、逐标签阈值、主主题评估及消融报告；选择候选后端。
- [ ] **M3：受控 LLM 与主动学习。** 增加结构化证据建议、预算/超时/缓存、疑难与随机审计选样、人工纠错和批次撤销；按效果决定是否测试 B5–B7。
- [ ] **M4：增量工程接入。** 实现独立数据库、持久化任务、逐内容版本幂等、过期结果拒绝及分类结果 delta 发布。证明不触发历史重分类，不阻塞采集与在线读取。
- [ ] **M5：影子验证。** 至少覆盖一个完整的新论文工作周，比较质量、重点主题表现、公开标签差异、成本、积压和线上延迟。人工检查新增/移除标签和待确认项。
- [ ] **M6：小范围启用与回滚演练。** 先对新纳管论文的固定小比例启用，再按验收报告扩大；保留规则模式、旧分类版本与查询快照。未满足门槛不自动升级默认模式。

每阶段用独立 PR 交付，Issue 作为总跟踪项。当前本地规则实验需单独审查/提交，不随本 Issue 自动发布。

## 10. 必须覆盖的测试

- 全部 14 个主题正例、难负例、多标签、主主题与信息不足情况。
- Marathoner 类型的 cs.CV Agent、普通小模型、仅使用 LLM、普通 benchmark 实验、图像对齐、泛 latency 等边界案例。
- 缩写、同义表述、长摘要末尾贡献、Unicode/HTML 清理、缺失/异常摘要。
- 训练/验证/测试论文家族不交叉；标签修改、训练数据与评估报告版本可追溯。
- 向量维度与模型版本不混用，文本变化失效缓存，语义相似度不能伪装为概率。
- LLM 输出非法、证据片段不存在、超时、限流、预算耗尽、模型不可用、worker 中断和重复任务。
- 新旧论文版本竞态：旧结果不能覆盖新文本或新人工审核。
- 原始数据库内容/结构、论文身份和收藏引用保持安全；模型只允许写独立派生库。
- 原始内容不变但异步标签完成时，查询结果能够增量更新；未纳管历史标签保持原样。
- 影子模式不改公开数据，候选校验失败保留旧发布指针，同一请求内查询版本一致。
- 旧 API、MCP、统计口径、在线内存与延迟回归；不确定候选不出现内部状态标签。

## 11. 上线与回滚

先部署关闭自动语义发布的代码与独立存储，完成离线实验与 shadow。发布模型产物、阈值、主题规范和样例索引的固定版本后，再启用新纳管记录。

人工标注库做持久备份，向量与任务缓存按独立保留策略管理。结果保留旧版本，不能就地覆盖到无法恢复。

回滚时停止新分类结果发布、恢复规则模式和之前的分类版本选择；需要恢复页面标签时切回经过确认的旧查询快照。保持原始库、账号/收藏库、原始采集水位和待处理任务不被清空。恢复时按幂等任务继续处理。

## 12. 研究依据与需要验证的假设

| 工作 | 研究依据 | 本项目拟验证的假设 |
| --- | --- | --- |
| [SciRepEval / SPECTER2，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.338/) | 科学文档表示在分类、回归、排序、检索之间需要任务适配 | 分类适配表示能否改善 14 主题，优于直接用检索向量 |
| [ASPIRE，NAACL 2022](https://aclanthology.org/2022.naacl-main.331/) | 句子级多向量与细粒度方面匹配 | 多方面表示能否改善 Agent/RL/后训练等交叉分类；原论文相似度结论不直接等于分类收益 |
| [SciMult，Findings of EMNLP 2023](https://aclanthology.org/2023.findings-emnlp.820/) | 科学文献的分类、引用、检索多任务表示 | 预训练过论文分类任务的编码器是否更适合本项目 |
| [SetFit，2022 arXiv](https://arxiv.org/abs/2209.11055) | 少样本对比学习与分类头 | 少量真实标注下，微调相对冻结向量的收益与训练成本 |
| [SEP-MLDC，Findings of NAACL 2025](https://aclanthology.org/2025.findings-naacl.212/) | LLM 标签语义扩展、长尾伪样本和标签引导特征 | 丰富主题定义与样例是否改善长尾类别；合成样本需隔离验证 |
| [GLiClass，2025 arXiv](https://arxiv.org/abs/2508.07662) | 零/少样本序列分类及多标签反馈训练 | 标签描述驱动模型能否在低标注量下取得更好成本/质量平衡 |
| [X-MLClass，EMNLP 2024](https://aclanthology.org/2024.emnlp-main.841/) | 极弱监督下迭代发现标签及长尾方向 | 作为未来发现细分主题的参考，本期不自动改变顶层标签 |
| [ActiveLLM，TACL 2026](https://aclanthology.org/2026.tacl-1.1/) | 使用 LLM 主动选择值得标注的文本 | 主动选样相对随机抽样能否以相同审核预算改善分类 |

论文中的性能数字不直接作为本项目收益承诺。候选模型还需要核对实际权重、许可证、依赖、输入长度、推理资源和输出校准。
