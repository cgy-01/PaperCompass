# 源码发布检查

本文是维护者检查表，不是自动部署脚本。整理仓库不应修改生产数据库、覆盖运行配置或重启网站。

## 提交前

1. 运行 `git status --short`，确保新增核心模块、模板、主题、部署文件、文档和测试被明确纳入提交计划；本地能运行不代表 Git 已收录。
2. 检查 `git diff --cached --name-only` 和 `git diff --cached`。不提交运行目录、虚拟环境、数据库及 sidecar、缓存、日志、密钥和真实收件人信息。
3. `.gitignore` 不会清除已跟踪文件，也不会清除 Git 历史。已跟踪的生成元数据应取消跟踪并保留磁盘文件；如曾提交真实凭据，应先撤销凭据，再单独处理历史。
4. 根目录的本地配置副本被忽略；公开模板在 `src/paper_firehose/system/config/`。模板和示例邮件配置中只使用示例值。
5. 检查素材来源和许可，代码 LICENSE 不自动覆盖高校标识。

## 新仓库的首次提交

当前开发仓库带有既有 Git 历史，历史中曾收录 `assets/matched_entries_history.db` 和 `assets/seen_entries.db`。忽略当前目录或删除当前版本不能从旧提交中移除它们。

首次公开独立仓库时，使用经过检查、不含 `.git` 的源码快照，在单独目录初始化新仓库。不要直接将当前开发仓库的全部分支、标签或镜像推送到新地址。现有开发目录和历史保留不动；源码快照保留 LICENSE 与必要说明，不包含运行库、校徽或个人配置。

## 可复现性

在新的克隆目录、独立虚拟环境和空数据目录中执行 README。确认无需开发者个人路径、生产数据库或 LLM 密钥，即可生成并启动空工作台。执行 `npm ci` 准备图标；采集测试使用模拟来源，首次真实采集单独运行。

```bash
python -m pytest -q
git diff --check
```

本地验证不能替代外部来源可达性检查。不要从生产数据目录运行测试或发布构建。

## GitHub 工作流

- 测试工作流只验证源码，不部署生产网站，不读取生产密钥。
- 包构建／发布工作流仅手动触发，发布还需显式选择；首次公开源码不等于发布 PyPI 包。
- 其他手动 Pages/文档工作流不是当前服务器的部署方式，执行前应阅读对应配置，不能将生产数据放到数据分支或发布附件中。

当前仍以源码安装为支持路径。公开前检查实际暂存内容与生成包内容，确认没有将本地 `system/` 目录中的私人文件打包。
