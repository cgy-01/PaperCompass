# 论文主题分类与增量升级

本文面向维护者，不加入网站用户文档白名单。

## 当前方案

每日 arXiv 任务、官方会议同步、可选 OpenAlex 检索和查询库发布，统一调用 `TopicClassifier`。它是本地、可解释的证据规则分类器，不是 LLM 或向量语义分类器；不访问模型接口、不下载模型、不增加运行依赖。

arXiv 分类只决定采集范围。每篇已获取论文都检查全部已配置的重点主题，例如 cs.CV 中的 Agent 论文可以归入 Agent。未配置的来源仍不会被自动采集，采集时间窗口保持不变。

候选召回与确定归类分开执行。命中过原有主题词或带必要语境的专属别名，但证据不足以确认主题的 arXiv 论文，仍然入库并可按标题、作者、摘要检索；不强行归入主题。没有任何候选信号的论文继续跳过。

## 判断过程

1. 规范化 HTML 实体、Unicode 连字符，按标题及摘要句子提取证据。
2. 区分专属术语与歧义术语。Infra 的 latency、throughput、scheduler 等需要 AI 语境和贡献证据；安全主题排除图像、几何、蛋白序列对齐等明确的其他含义。
3. 标题证据权重为 6；“我们提出、发布、设计、证明”等贡献句证据为 4；普通摘要证据为 2；背景、基线和“使用某模型”证据为 0.5。
4. 同一匹配词组只保留最高权重，忽略大小写及连字符、空格差异。重复关键词、重复句子和同一摘要在两个字段中存储均不会增加它的权重。最多累计四个有效词组，低于 2 的背景权重不进入通过判断。
5. 内置主题的通过门槛为 `max(3, min_matches + 1)`。数据与评测的摘要证据必须出现在贡献句中；不因为在普通 benchmark 上做实验就归类。LLM 需要明确的大模型术语，普通 neural network 或小模型规模数字不作为 LLM 证据。
6. 允许多个主题同时通过。主主题按证据权重选择，同权重优先更具体的匹配概念，再按主题 key 稳定排序，不受菜单顺序影响。

分值是内部证据权重，不是置信概率、论文质量分或 API 的 `rank_score`。主主题用于环图，各主题计数仍允许一篇计入多个方向。

默认配置在 `src/paper_firehose/system/config/topic_classification.yaml`。它是随代码发布的内置策略，不依赖复制到运行目录。只有运行主题的 `filter.pattern` 与同名内置模板一致时自动应用该策略，避免覆盖维护者已有的自定义过滤语义。

显式自定义 `filter.pattern` 仍使用统一的去重、背景降权和主主题排序，门槛为 `max(2, min_matches + 1)`。如需为自定义规则增加语境约束，可以在对应运行主题 YAML 中增加：

```yaml
classification:
  anchors: '\b(LLM serving|KV cache|latency)\b'
  context: '\b(LLM|GPU|model serving|KV cache)\b'
  ambiguous: 'latency'
  exclude: '\b(unrelated example)\b'
  contribution_required: false
```

`context` 是必要条件，不是分类证据；`ambiguous` 中的词还需要贡献句支持；`exclude` 仅排除命中的句子。正则使用不区分大小写的 Python 语法，必须避免无界嵌套重复。配置错误会明确失败，不会静默忽略该主题。调试日志会输出命中主题、权重和对应的有限长度证据片段。

## 数据安全与生效范围

- 不修改原始数据库表结构，不更换论文 ID，不改变收藏引用和公开 API 字段。
- 不启动历史回补，不修改 arXiv 成功水位，不增加抓取来源或抓取窗口。
- 已发布查询库继续使用原来的内容指纹。仅升级分类器代码或内置证据策略，不使未变化的历史记录重新分类；新增或原始内容发生变化的记录使用新策略。查询库 metadata 记录当前分类器版本及 `new_or_changed` 范围，不能据此声称全库已按新规则处理。
- 运行主题目录、`filter.pattern`、自定义 `classification`、显示名称或其他目录配置被修改时，既有签名机制仍可能触发全量重分类。此次升级不改这些运行配置。不要删除查询库、修改格式版本或主动变更目录签名来尝试“刷新分类”。
- 会议全量目录收录原则不变，没有研究主题的正式会议论文仍然保留。新 arXiv 论文没有候选信号时才会被过滤；本次减少明确误判，不承诺全量 AI 论文覆盖。
- 待确认 arXiv 候选在原有 `topics` 文本字段中使用内部标记 `_classification_pending`，不新增数据库列。发布时不把它放入 `topics`、`topicKeys`、主主题或搜索文本，不显示“未分类”标签；这类论文计入总量和信息完整度，不计入已归类数量。报告里的 `inserted_pending` 是本轮新增论文中待确认的子集，后续有确定证据的版本会移除该标记。
- 旧手动 `filter` 命令保留兼容的字面匹配行为，不属于每日自动任务；不要用它代替 `update --scope arxiv`。

候选查询库仍先在后台构建、校验，再原子发布。失败保留旧版本，不需重启在线阅读服务。分类器升级只需要部署源码，不需要替换或清空服务器运行数据。

## 验证与回滚

```bash
python -m pytest tests/test_classification.py tests/commands/test_arxiv.py \
  tests/commands/test_official_sources.py tests/commands/test_openalex.py \
  tests/test_query_store.py tests/commands/test_update.py -q
```

测试覆盖全部重点主题正例、跨来源召回、背景/歧义/重复词误判、主主题稳定排序、非法规则、历史指纹保留、原始库不写入和发布失败回退。真实样本耗时检查与这些回归测试都不能替代人工标注数据集上的准确率、召回率评估。

回滚代码不需要数据库迁移。已经发布的标签保留在各查询快照里；若需同时回滚本轮标签，按自动更新管理员文档恢复之前的 `current.json`，保留其指向的数据库文件。不要删除原始库、收藏库或采集水位。
